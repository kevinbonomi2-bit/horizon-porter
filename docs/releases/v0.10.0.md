# horizon-porter 0.10.0

Ports for Horizon's mod API, made for Horizon build `f1bb66f`, and Create's machines a long way
further along.

**Re-port your mods with this version** (`port --force`, or Port again in the app), then
`translate --refresh`.

## Ports for Horizon's mod API

Horizon merged its mod API on 2026-11-16, and native mods of the system before it (horizon-mixins
bundles built into the game, `.hnmod`) don't load on builds since. A port is now written both ways:

- **`api/`, for Horizon builds from 2026-11-16 on**, made for build `f1bb66f` (2026-11-22): a
  native mod on the mod API that the launcher compiles against that build's mod SDK, without
  rebuilding the game. Its `horizon-mod.toml` pins `f1bb66f` and the horizon-mixins tool its
  launcher pins; its `Cargo.toml` names the API by the SDK's path, the only form the launcher takes.
- **`mixins/<id>/`, for older builds** (Nightly 2026-11-13 and before): the bundle, as before.

Both run the same translated code: `translate` ports it once. `build` and `install` pick the one
your launcher takes, `package` writes `api/` as `<id>-<version>.hmod`, and `--no-api` leaves it out.

## Block entities reach as far on the mod API

A block entity's tick on the mod API used to see only the blocks beside it. It now reaches as far
as the bundle's, through the API alone (no `[[native.*]]` rows, so a port needs only the SDK):

- **any of the mod's block entities by position**, itself included while it ticks (a belt walking
  its chain), and the **containers around it or at any place**, a chest's and a hopper's too;
- **saved values and slots it changes in other block entities**, written back after its tick;
- **items moved through item handlers** on the right face (a funnel's take and give, a machine's
  push and pull), each move in a transaction;
- **kinetic networks** (stress and capacity added up across the members), **tanks and energy**, and
  the mark on items it ejects so it doesn't take them back in.

Each port with block entities gets tests of its own for this, which `cargo test` in `api/` runs
against the mod API's fake host.

## Create

Create's source ([docs/CREATE.md](../CREATE.md)), worked through as the porter's hardest test. What
it took helps any mod built like it.

Checked in game on Horizon `66f3981` (the bundle): 29 checks pass, from the motor, shafts,
cogwheels, gearboxes, clutches, gearshifts and the hand crank to the millstone grinding wheat, the
press making sheets on a depot and the mixer making alloy in a basin, and the belt tests pass 4 of 4:

- **Belts** are made with the belt connector, carry items along their chain at the motor's speed,
  and hand them to a depot at the end. Items dropped on any segment ride, in Java's order.
- **Belt funnels** push a chest's items onto a belt and pull what passes into a chest, every item
  accounted for. **Hoppers** reach Create's machines.
- **Value boxes** open their board as in Java on all 14 blocks that have one, with Java's labels,
  ranges and rows; a creative motor's speed is set from it.
- **Kinetic networks** add up stress and capacity; **machines face the player** and draw their
  moving parts.

## What the porter learned

- **A block entity's state can hold lists** of the mod's own classes (a belt's `List<TransportedItemStack>`),
  and its fields start where Java's constructors start them (a filter's 64).
- **A behaviour asked of another block entity** (`DirectBeltInputBehaviour.handleInsertion`,
  `InvManipulationBehaviour.insert`) is ported once for every block entity that sets it up, and a
  mod's helpers that work on the level or a kept part are functions of their own.
- **Prompts show more of the Java that matters**: the methods a function calls on what its code
  makes or keeps (`handler.insertItem`, `stack.compareTo`), not the Java of helpers already ported,
  trimmed only by what a prompt is over Haiku's 100k-token price line.
- **`translate --jobs N`** asks for several functions at once.
- A list of block entities or entities is no longer mistaken for a list of values (VillagersPlus
  wrote a struct twice).

## Checked on `f1bb66f`

Horizon's GitHub was unreachable as this was made, so no SDK could be downloaded: `f1bb66f`'s mod
SDK was built here from Horizon's source, as its own CI builds it, and Create's `api/` was compiled
and linked against it as the launcher does. On that build's dedicated server (on prepared game files
from the Nightly of 2026-11-11), Create loads, its recipes are read, and **24 of the 29 Create checks
pass**: every one a server console can run. Motors, shafts, cogwheels (diagonal meshing too),
gearboxes, clutches and gearshifts turn as in Java; the millstone grinds wheat, the press makes iron
sheets on a depot and the mixer makes andesite alloy in a basin. The other five need a player
(taking items back by hand, placing a press and a crank by hand, clicking the crank), as do the belt
tests: those ran on the bundle only.

That run found three things the mod API needed, fixed in this version: a code mod's own recipe types
are registered (or the game won't load its recipes), recipe ingredients in the form Create's files
keep (`{"item": ..}`) are read as 26.3's, and a tick sees the items of the block entities it reaches
(a press, the depot under it) and the blocks diagonally around it (cogwheels).

Also checked: Create (with its translated code), Farmer's Delight, Waystones, Beautify,
VillagersPlus, Friends & Foes, Naturalist, Macaw's Fences and six test mods compile against
`f1bb66f`'s `horizon-mod-api` with no error or warning, and the glue's own tests pass against the
API's fake host. Not yet played in a client on `f1bb66f`: a world with a player, belts, screens.

# horizon-porter 0.8.0

Ported mods now load reliably, look right, and their blocks start to *behave* like they do in Java.
This release comes out of porting 150 popular 26.3 mods from Modrinth and playing the results:
Macaw's Doors, Windows and Roofs, Biomes O' Plenty and Tom's Simple Storage were played in Horizon,
and every bug found there is fixed in the porter, so it fixes every mod with the same pattern.

**Re-port your mods with this version** (`port --force`, or Port again in the app). Translated
functions are kept.

## Content mods load

Horizon refuses *all* content mods when one file or block is wrong. 0.7.0 often hit one of these;
0.8.0 doesn't:

- JSON files with a byte order mark (Macaw's tags) are cleaned, and unreadable JSON is left out.
- A block never copies a vanilla block that has no item, a growing plant (vines, kelp), or anything
  that isn't a block of 26.3.
- Blocks Java gives no item (wall signs, liquids, potted plants, leftover blockstates) get none, so
  the creative tab has no blank slots.

## Blocks look and feel right

- **Creative tabs.** Each mod gets its own tabs, with the title, icon and items its code builds.
- **Shapes.** Thin blocks (curtains, blinds, shutters, buds, roofs) take their outline and
  collision from their own models instead of a full cube. Plants can be walked through.
- **Facing.** Blocks face the way Java places them: the porter reads each block's
  `getStateForPlacement` (a quarter turn for Macaw's curtains, toward the player for blinds).
- **Every state draws.** A direction the blockstate never names gets a model, so no more invisible
  blocks placed facing south or west (Macaw's resizable windows).
- **Java's own states.** Properties Java's code uses but the blockstate never names (a garage
  door's `powered`) are declared, and blocks start in Java's default state.
- **Better templates.** Stairs-shaped blocks copy stairs, one-block hinged blocks (shutters) copy a
  trapdoor instead of a two-block door, potted plants copy a flower pot.
- **Signs** place the mod's own wall sign. **Custom model loaders** (Lootr's barrel) draw.

## Block code comes along

New: blocks that *do* things in Java now do them in Horizon. For every block class whose Java
defines `getStateForPlacement`, `useItemOn`/`useWithoutItem` or `updateShape`, the port wires
Horizon's placement, right-click and neighbour hooks and writes a function to translate. After
**Translate**, Macaw's shutters pick their hinge from where you click, blinds open, close and raise,
windows join the ones around them, and garage doors roll down to the ground and back up.

Translation uses the Claude API. The key you saved in the app now works from the command line
too, and the default model (Claude Haiku 5.5) is cheap: Macaw's Doors cost under a cent.

## Machines (M6, M7)

- Block entity renderers can draw standalone models, and mods can draw over game screens.
- Fluid tanks and energy buffers, items moving between a machine and its neighbours, and kinetic
  blocks (shafts that turn with their neighbours).

## More mods port

Registrations through a mod's own wrappers and registrars, ids kept in constants, colored block
sets, Kotlin mods, mobs (as a zombie, villager or wandering trader with the mod's attributes) and
mob effects. Of the 150 surveyed mods, all port, and every one whose code the porter wires builds
against Horizon's hook API.

## New checks

- **`tools/horizon_check.py`** loads a port with Horizon's own code (the content build, a world's
  rules and every block's models) and says what would keep it from loading or drawing.
- **`tools/play_check.py`** plays a port in the real game through `horizon-ctl`: it places every
  block in a test world, right-clicks the ones that act, and reports faults.
- **`tools/survey.py --horizon`** runs Horizon's checks on every surveyed mod.

## Not yet

- **Mod biomes.** Horizon can't add new biomes yet, so Biomes O' Plenty's blocks and items work but
  its biomes don't generate. **Boats** need Horizon to add a boat entity.
- **Redstone** on ported blocks (`neighborChanged`), and a click while **sneaking**, need hooks
  Horizon doesn't have yet. Clicks work.
- **Item behaviour** (`useOn`, `use`) isn't carried over yet: items exist and look right, but their
  right-click code is the next step.
- Mobs use a vanilla mob's AI.

## Upgrading

Re-port with `--force` (the app: Port again). The content mod is rebuilt from scratch and your
translated functions are kept. Blocks already placed in a world keep their old states: place new
ones to see the fixes.
